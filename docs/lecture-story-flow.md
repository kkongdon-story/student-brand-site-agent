# 수업 스토리 흐름

이 문서는 1시간 강의를 이야기처럼 끌고 가기 위한 강사용 진행안입니다.

수업의 핵심은 “AI로 홈페이지를 만든다”가 아닙니다. 수강생이 자기 브랜드를 AI가 이해할 수 있는 말로 바꾸고, 그 기준으로 홈페이지를 만들어보는 경험을 하게 하는 것입니다.

## 한 줄 메시지

```text
홈페이지는 코딩 실력 자랑이 아니라, 처음 보는 사람이 나를 이해하고 다음 행동을 하게 만드는 브랜드 창구입니다.
```

## 강의의 감정선

```text
홈페이지가 왜 필요한가
-> 내 브랜드를 먼저 선명하게 해야 한다
-> AI에게 인터뷰를 시켜 생각을 구체화한다
-> 홈페이지의 기본 구조를 아주 쉽게 이해한다
-> 레퍼런스와 컴포넌트 이름으로 AI에게 정확히 말한다
-> 실제 결과물은 한 번에 나오지 않고 수정하면서 좋아진다
-> 보안과 관리, 배포까지 AI에게 단계별로 물어보며 확장한다
```

## 0-5분: 오늘 만드는 것은 무엇인가

### 목적

수강생이 “오늘 내가 무엇을 만들고 왜 만드는지”를 이해하게 합니다.

### 강사용 멘트

```text
홈페이지를 만드는 이유는 여러 가지가 있습니다.

SaaS 서비스를 소개하는 페이지일 수도 있고,
상품을 판매하는 상세페이지일 수도 있고,
강의나 상담 신청을 받는 랜딩페이지일 수도 있습니다.

그런데 오늘 우리의 목적은 조금 더 단순합니다.

오늘은 나를 알리기 위한 창구,
즉 개인 브랜드 홈페이지를 만들어볼 겁니다.

처음 보는 사람이 이 페이지를 보고
"이 사람은 어떤 사람이지?"
"무엇을 도와주는 사람이지?"
"어디로 연락하면 되지?"
를 알 수 있게 만드는 것이 목표입니다.
```

### 화면에 보여줄 것

- 완성 예시 첫 화면
- 상담/자료/스레드/블로그 링크가 들어간 부분

### 강조할 것

- 오늘은 완벽한 개발자가 되는 수업이 아닙니다.
- 오늘은 AI에게 홈페이지를 맡기는 방법을 배우는 수업입니다.

## 5-12분: 브랜딩은 예쁜 디자인보다 먼저다

### 목적

홈페이지를 만들기 전에 브랜드 재료가 먼저 필요하다는 것을 납득시킵니다.

### 강사용 멘트

```text
브랜딩을 홈페이지에 녹이려면 먼저 내가 무엇을 하려는지 알아야 합니다.

나는 누구를 돕는 사람인지,
사람들에게 무엇을 줄 수 있는지,
사람들이 나를 보고 어떤 행동을 하길 원하는지,
이런 것들이 먼저 정리되어야 합니다.

이게 없으면 AI에게 아무리 "예쁘게 만들어줘"라고 해도
그럴듯하지만 나와 상관없는 페이지가 나옵니다.
```

### 질문 예시

```text
나는 누구를 돕고 싶은가?
사람들은 나를 왜 찾아야 하는가?
내가 줄 수 있는 것은 정보인가, 상담인가, 강의인가, 자료인가?
홈페이지를 본 사람이 눌러야 할 버튼은 무엇인가?
```

### 연결할 파일

- `brand-materials.md`

## 12-20분: AI에게 인터뷰를 시킨다

### 목적

두루뭉술한 생각을 AI와의 인터뷰로 선명하게 만드는 방식을 보여줍니다.

### 강사용 멘트

```text
막상 홈페이지를 만들려고 하면 대부분 여기서 막힙니다.

"뭘 써야 하지?"
"내가 뭘 원하는 거지?"
"사람들이 이걸 보면 뭘 느꼈으면 좋겠지?"

그래서 바로 홈페이지를 만들지 않습니다.
먼저 AI에게 인터뷰를 시킵니다.

한 번에 다 물어보라고 하지 말고,
하나씩 질문하게 만드는 것이 중요합니다.
우리는 답을 하면서 내 생각을 구체화하고,
AI는 그 답을 홈페이지 재료로 바꿉니다.
```

### 시연 프롬프트

```text
personal-brand-site 스킬을 사용해서 개인 브랜드 홈페이지를 만들고 싶어.
바로 코딩하지 말고 1단계 브랜드 재료 정리부터 질문을 하나씩 해줘.
내 답변을 바탕으로 brand-materials.md를 만들어줘.
```

### 강조할 것

- AI는 코딩만 하는 도구가 아니라 질문을 시킬 수 있는 도구입니다.
- 좋은 결과물은 좋은 질문에서 시작합니다.

## 20-28분: 홈페이지의 큰 구조를 쉽게 이해한다

### 목적

프론트엔드, 백엔드, 서버, 배포 개념을 겁나지 않게 설명합니다.

### 강사용 멘트

```text
브랜드 DNA가 어느 정도 세워지면,
홈페이지가 어떤 구조로 만들어지는지도 아주 가볍게 알아야 합니다.

어렵게 생각하지 않아도 됩니다.

프론트엔드는 사람들이 보는 화면입니다.
버튼, 글자, 이미지, 메뉴, 움직임이 여기에 들어갑니다.

백엔드는 뒤에서 데이터를 저장하거나 처리하는 부분입니다.
오늘 만드는 개인 브랜드 홈페이지는 복잡한 백엔드가 없어도 됩니다.

서버는 내 홈페이지 파일을 인터넷에 보여주는 장소입니다.
우리는 Vercel 같은 서비스를 써서 쉽게 올릴 겁니다.

오늘은 정적 홈페이지로 갑니다.
즉 HTML, CSS, JavaScript 파일만으로도 충분히 만들 수 있는 구조입니다.
```

### 쉬운 비유

```text
HTML은 뼈대입니다.
CSS는 옷과 분위기입니다.
JavaScript는 움직임과 반응입니다.
Vercel은 그 집을 인터넷에 올려주는 주소입니다.
```

### 강조할 것

- 오늘은 데이터베이스를 연결하는 수업이 아닙니다.
- 브랜딩 창구는 정적 홈페이지로도 충분히 시작할 수 있습니다.

## 28-38분: 레퍼런스와 컴포넌트 이름이 필요하다

### 목적

디자인을 못하는 사람도 AI에게 정확히 피드백할 수 있도록, 레퍼런스와 웹 구성 요소 이름의 필요성을 설명합니다.

### 강사용 멘트

```text
우리는 전문 웹디자이너가 아닙니다.
그래서 머릿속에 완성된 화면이 잘 없습니다.

이럴 때 필요한 것이 좋은 레퍼런스입니다.

레퍼런스는 베끼는 대상이 아닙니다.
내가 원하는 감각을 AI에게 설명하기 위한 재료입니다.

또 하나 중요한 것이 컴포넌트 이름입니다.

상단 메뉴를 Navigation Bar라고 부르고,
첫 화면을 Hero 또는 Masthead라고 부르고,
신청 버튼 영역을 CTA라고 부른다는 정도만 알아도
AI에게 훨씬 정확하게 피드백할 수 있습니다.
```

### 보여줄 자료

- `docs/reference-site-guide.md`
- Lapa Ninja, Awwwards, Siteinspire, Landing Love, 60fps 예시

### 수강생에게 줄 미션

```text
레퍼런스는 딱 3개만 고릅니다.

1. 구조 참고: 첫 화면과 섹션 순서
2. 분위기 참고: 색감, 폰트, 질감
3. 움직임 참고: hover, click, scroll 반응
```

### AI에게 줄 형식

```text
1. 사이트 주소 또는 스크린샷:
2. 마음에 드는 부분:
3. 내 홈페이지가 가져오면 좋을 것:
4. 절대 그대로 따라 하면 안 되는 것:
5. AI에게 줄 자료:
   URL / 스크린샷 / 색상 / 폰트 / 부품 이름 / 움직임 설명
```

## 38-45분: 내가 한 결과물과 대화 기록을 보여준다

### 목적

AI 결과물이 한 번에 완성되는 것이 아니라, 반복 수정으로 좋아진다는 현실적인 감각을 줍니다.

### 강사용 멘트

```text
시간상 여러분이 모든 과정을 처음부터 끝까지 완성하기는 어렵습니다.

그래서 제가 먼저 해본 결과물을 보여드리겠습니다.

중요한 건 결과물만 보는 게 아닙니다.
대화 기록을 같이 봐야 합니다.

처음 결과는 완벽하지 않았습니다.
레퍼런스와 다르게 나왔고,
캐릭터 퀄리티도 낮았고,
인터랙션도 부족했습니다.

그런데 그게 실패가 아닙니다.
AI 작업에서 진짜 실력은 첫 결과물을 보고 다시 지시하는 데서 나옵니다.
```

### 보여줄 것

- 완성 예시 사이트
- `reference-dna.md`
- `prompt-pack.md`
- `DESIGN.md`
- QA 리포트 또는 스크린샷

### 강조할 것

- 첫 결과물은 초안입니다.
- “별로야”가 아니라 구체적으로 고쳐달라고 해야 합니다.

### 수정 요청 예시

```text
첫 화면이 너무 평범합니다.
Hero 문장을 더 크게 하고, 카드 수를 줄이고,
마우스를 올렸을 때 반응이 더 분명하게 보이게 해주세요.

단, 모바일 반응형과 DESIGN.md의 브랜드 방향은 유지해주세요.
```

## 45-53분: 실시간 시연

### 목적

에이전트가 실제로 어떤 순서로 움직이는지 보여줍니다.

### 시연 흐름

1. Codex에서 `personal-brand-site` 스킬 시작
2. 1단계 브랜드 질문 한두 개 답변
3. 2단계 레퍼런스 가이드 보여주기
4. URL 또는 스크린샷을 넣으면 어떤 질문을 하는지 보여주기
5. `reference-dna.md`와 `prompt-pack.md`가 어떻게 생기는지 설명
6. `DESIGN.md`가 왜 계약서인지 설명
7. 예제 사이트 QA 결과 보여주기

### 강사용 멘트

```text
여기서 중요한 건 명령어를 외우는 게 아닙니다.

AI에게 바로 만들라고 하는 대신,
브랜드 재료, 레퍼런스 증거, 프롬프트팩, DESIGN.md를 차례대로 만들게 하는 흐름을 익히는 겁니다.
```

## 53-57분: 보안과 관리

### 목적

수강생이 공개하면 안 되는 정보와 유지관리 관점을 이해하게 합니다.

### 강사용 멘트

```text
홈페이지를 만들 때 조심해야 할 것도 있습니다.

API 키, 비밀번호, 개인 연락처, 결제 정보 같은 것은 코드에 그대로 넣으면 안 됩니다.

그리고 AI가 없는 경력이나 숫자를 만들어낼 때가 있습니다.
이런 건 반드시 사람이 확인해야 합니다.

브랜딩 페이지는 신뢰를 만드는 페이지이기 때문에,
없는 내용을 멋있게 쓰는 것보다 정확한 내용을 분명하게 쓰는 것이 더 중요합니다.
```

### 체크리스트

- API 키를 코드에 넣지 않기
- 비밀번호를 GitHub에 올리지 않기
- 없는 경력, 후기, 숫자 만들지 않기
- 카카오톡/인스타/스레드 링크가 맞는지 확인하기
- 모바일에서 깨지지 않는지 확인하기

## 57-60분: GitHub, Vercel, 그리고 관점

### 목적

배포를 너무 어렵게 느끼지 않게 만들고, AI에게 단계별 도움을 요청하는 관점을 전달합니다.

### 강사용 멘트

```text
마지막으로 서버에 올리는 방법입니다.

GitHub는 내 홈페이지 코드를 보관하는 곳이고,
Vercel은 그 코드를 실제 링크로 만들어주는 곳입니다.

처음에는 낯설 수 있지만,
이것도 AI에게 단계별로 물어보면 됩니다.

"내가 만든 정적 홈페이지를 GitHub에 올리고 Vercel로 배포하고 싶어.
윈도우 기준으로 한 단계씩 설명해줘.
내가 따라 하면 다음 단계로 넘어가줘."

이렇게 말하면 됩니다.

오늘의 핵심은 모든 명령어를 외우는 것이 아닙니다.
내가 원하는 결과를 AI가 이해할 수 있게 정리하고,
AI에게 단계별로 일을 시키는 관점을 배우는 것입니다.
```

### 마무리 멘트

```text
오늘 만든 홈페이지는 최종본이 아니라 시작점입니다.

레퍼런스를 바꾸면 분위기가 바뀌고,
문장을 바꾸면 브랜드가 바뀌고,
움직임을 바꾸면 기억에 남는 방식이 바뀝니다.

중요한 건 내가 직접 다 코딩하지 않아도,
AI와 대화하면서 내 브랜드 홈페이지를 계속 발전시킬 수 있다는 감각입니다.
```

## 강사의 운영 원칙

- 초보자에게 한 번에 많은 도구를 보여주지 않습니다.
- 전문용어는 말하되 바로 쉬운 말로 번역합니다.
- 결과물보다 과정과 수정 방식을 보여줍니다.
- “AI가 한 번에 다 해준다”가 아니라 “AI에게 일의 순서를 잡아준다”를 강조합니다.
- 수강생이 막히면 “지금은 정답을 찾는 시간이 아니라 재료를 선명하게 만드는 시간”이라고 안내합니다.
