# 1시간 강의 대본 v1

주제: 바이브코딩으로 나를 알리는 개인 브랜드 홈페이지 만들기

목표: 수강생이 코드를 외우는 것이 아니라, AI에게 홈페이지 제작을 맡기기 위한 사고방식과 진행 순서를 이해하게 한다.

## 전체 메시지

```text
홈페이지는 예쁜 배경을 만드는 일이 아니라,
처음 보는 사람이 나를 이해하고 다음 행동을 하게 만드는 구조를 만드는 일입니다.

AI는 코딩을 도와줄 수 있지만,
내가 누구인지, 무엇을 원하는지, 어떤 느낌을 원하는지는 그냥 알아서 알 수 없습니다.

그래서 오늘은 AI에게 바로 "홈페이지 만들어줘"라고 하지 않고,
브랜드 재료, 레퍼런스, 디자인 지시서, 수정 요청, 배포 관점을 차례대로 배웁니다.
```

## 0-3분: 오프닝

### 말하기

안녕하세요. 꽁돈입니다.

오늘은 바이브코딩으로 홈페이지를 만들어보는 이야기를 해보려고 합니다.

그런데 오늘 수업은 HTML, CSS 문법을 외우는 수업은 아닙니다. 물론 결과적으로 홈페이지가 만들어지긴 할 건데요. 더 중요한 건 “AI에게 어떻게 홈페이지 제작을 맡길 것인가”입니다.

요즘은 AI에게 “홈페이지 만들어줘”라고 하면 일단 뭔가 나오긴 합니다. 그런데 문제는 그다음입니다. 결과물이 너무 흔한 템플릿 같거나, 내 브랜드와 상관없거나, 마음에 안 드는데 어디를 어떻게 고쳐달라고 해야 할지 모르는 경우가 많습니다.

그래서 오늘은 홈페이지 하나를 만드는 과정을 통해서, AI에게 내 의도를 전달하는 방법을 같이 보겠습니다.

### 보여줄 화면

- 완성 예시 첫 화면
- 카카오톡/스레드/블로그 링크가 있는 마지막 영역

### 피드백 포인트

- 오프닝이 너무 길면 2분으로 줄인다.
- 청중이 완전 초보라면 “코딩 수업이 아니다”를 더 강하게 말한다.

## 3-8분: 왜 홈페이지를 만드는가

### 말하기

먼저 홈페이지를 왜 만드는지부터 짚고 갈게요.

홈페이지를 만드는 이유는 다양합니다.

어떤 사람은 SaaS 서비스를 소개하려고 만들 수 있고, 어떤 사람은 상품을 판매하려고 만들 수 있고, 어떤 사람은 강의나 상담 신청을 받으려고 만들 수 있습니다.

그런데 오늘 우리의 목적은 조금 더 단순합니다.

오늘은 “나를 알리기 위한 창구”로서의 홈페이지를 생각해보겠습니다.

처음 보는 사람이 내 홈페이지에 들어왔을 때 이런 걸 알 수 있어야 합니다.

이 사람은 누구지?

무엇을 도와주는 사람이지?

어떤 자료나 강의나 상담을 받을 수 있지?

어디로 연락하면 되지?

이 네 가지가 보이면, 개인 브랜드 홈페이지로서 일단 출발은 할 수 있습니다.

그러니까 오늘 만드는 건 거창한 서비스가 아니라, 나를 소개하고 다음 행동으로 연결하는 개인 브랜드 명함이라고 생각하면 됩니다.

### 핵심 문장

```text
오늘 만드는 홈페이지는 나를 알리고, 이해시키고, 다음 행동으로 연결하는 개인 브랜드 명함입니다.
```

### 보여줄 화면

- 예시 사이트의 Hero
- CTA 버튼
- Contact section

## 8-15분: 브랜딩은 디자인보다 먼저다

### 말하기

그럼 바로 홈페이지를 만들면 될까요?

저는 여기서 바로 만들면 안 된다고 생각합니다.

왜냐하면 홈페이지에 브랜딩을 녹이려면, 먼저 내가 무엇을 하려는지 알아야 하기 때문입니다.

나는 누구를 돕고 싶은지.

사람들에게 무엇을 줄 수 있는지.

사람들이 나를 보고 어떤 행동을 하길 원하는지.

내가 얻고 싶은 효과는 무엇인지.

이런 것들이 먼저 정리되어야 합니다.

이게 정리되지 않은 상태에서 AI에게 “예쁘게 만들어줘”라고 하면, 그럴듯한 페이지는 나올 수 있습니다. 그런데 그 페이지가 나를 설명하지는 못합니다.

예쁘긴 한데 나와 상관없는 페이지가 되는 거죠.

그래서 오늘 첫 단계는 코딩이 아니라 브랜드 재료 정리입니다.

### 수강생에게 던질 질문

지금 여러분도 머릿속으로 한 번 생각해보세요.

나는 누구를 돕고 싶은가?

내가 줄 수 있는 것은 정보인가, 상담인가, 강의인가, 자료인가?

내 홈페이지를 본 사람이 가장 먼저 눌렀으면 하는 버튼은 무엇인가?

이 세 가지가 오늘 홈페이지의 뼈대가 됩니다.

### 보여줄 파일

- `brand-materials.md`

### 피드백 포인트

- 수강생이 조용하면 질문을 적게 하고 예시로 넘긴다.
- 시간이 있으면 1명만 구두로 예시를 받아도 좋다.

## 15-22분: AI에게 인터뷰를 시킨다

### 말하기

그런데 여기서 또 문제가 생깁니다.

막상 “내 브랜드를 정리해보세요”라고 하면 대부분 막힙니다.

뭘 써야 할지 모르겠고, 내가 뭘 원하는지도 애매하고, 사람들이 나를 어떻게 봤으면 좋겠는지도 두루뭉술합니다.

그래서 우리는 AI를 다르게 써볼 겁니다.

AI에게 바로 답을 달라고 하는 것이 아니라, 나에게 질문을 하게 만드는 겁니다.

예를 들면 이렇게 말할 수 있습니다.

```text
personal-brand-site 스킬을 사용해서 개인 브랜드 홈페이지를 만들고 싶어.
바로 코딩하지 말고 1단계 브랜드 재료 정리부터 질문을 하나씩 해줘.
내 답변을 바탕으로 brand-materials.md를 만들어줘.
```

여기서 중요한 건 “하나씩 질문해줘”입니다.

한 번에 질문을 10개 받으면 초보자는 또 막힙니다. 하나씩 물어보게 하고, 내가 답하고, AI가 그 답을 정리하게 하는 흐름이 좋습니다.

이 과정을 거치면 두루뭉술한 생각이 조금씩 선명해집니다.

### 강조

AI는 코딩만 하는 도구가 아닙니다.

좋은 질문을 하게 만들 수 있는 도구입니다.

좋은 홈페이지는 좋은 질문에서 시작됩니다.

### 보여줄 화면

- Codex에서 Stage 1 질문 예시
- `brand-materials.md` 예시

## 22-29분: 홈페이지 구조를 아주 쉽게 이해한다

### 말하기

브랜드 재료가 어느 정도 정리되면, 홈페이지가 어떤 구조로 만들어지는지도 아주 가볍게 알아야 합니다.

여기서 어려운 개발 이야기를 하려는 건 아닙니다.

딱 이 정도만 알면 됩니다.

프론트엔드는 사람들이 보는 화면입니다. 글자, 이미지, 버튼, 메뉴, 움직임이 전부 프론트엔드에 들어갑니다.

백엔드는 뒤에서 데이터를 저장하거나 처리하는 부분입니다. 회원가입, 결제, 게시판, 로그인 같은 것이 필요하면 백엔드가 중요해집니다.

그런데 오늘 만드는 개인 브랜드 홈페이지는 복잡한 백엔드가 없어도 됩니다.

우리는 정적 홈페이지로 시작할 겁니다.

정적 홈페이지는 쉽게 말하면 HTML, CSS, JavaScript 파일로 구성된 홈페이지입니다.

HTML은 뼈대입니다.

CSS는 옷과 분위기입니다.

JavaScript는 움직임과 반응입니다.

그리고 Vercel 같은 서비스는 이 파일들을 인터넷에 올려서 링크로 볼 수 있게 해주는 곳입니다.

### 핵심 문장

```text
오늘은 데이터베이스를 붙이는 수업이 아닙니다.
나를 알리는 브랜드 창구는 정적 홈페이지로도 충분히 시작할 수 있습니다.
```

### 보여줄 화면

- `site/index.html`
- `site/styles.css`
- `site/script.js`

### 피드백 포인트

- 개발 용어가 부담스러워 보이면 이 구간을 5분으로 줄인다.
- 비유 중심으로 설명한다.

## 29-38분: 왜 레퍼런스와 컴포넌트 이름이 필요한가

### 말하기

이제 디자인 이야기로 넘어가겠습니다.

우리는 대부분 전문 웹디자이너가 아닙니다. 그래서 머릿속에 완성된 화면이 잘 없습니다.

이때 필요한 것이 좋은 레퍼런스입니다.

레퍼런스는 베끼는 대상이 아닙니다.

내가 원하는 감각을 AI에게 설명하기 위한 재료입니다.

예를 들어 “홍대 감성으로 해줘”라고 하면 AI는 사람마다 다르게 이해합니다. 그런데 이렇게 말하면 훨씬 선명해집니다.

밝은 종이 배경.

큰 한글 타이포그래피.

손으로 정리한 듯한 섹션.

마우스를 올리면 살짝 반응하는 버튼.

스크롤하면 하나씩 드러나는 구성.

이렇게 말하면 AI가 디자인으로 바꿀 수 있습니다.

또 하나 중요한 것이 컴포넌트 이름입니다.

상단 메뉴는 Navigation Bar.

첫 화면은 Hero 또는 Masthead.

버튼 영역은 CTA.

자주 묻는 질문은 FAQ.

마지막 연락 영역은 Footer 또는 Contact Section.

이 정도 이름만 알아도 AI에게 피드백하기 쉬워집니다.

“위에 있는 거 좀 고쳐줘”가 아니라, “Navigation Bar의 버튼 간격을 줄여줘”라고 말할 수 있게 됩니다.

### 보여줄 자료

- `docs/reference-site-guide.md`
- Lapa Ninja
- Awwwards
- Siteinspire
- Landing Love
- 60fps

### 수강생에게 말하기

오늘은 레퍼런스를 무한정 찾지 않습니다.

딱 3개만 고릅니다.

구조 참고 하나.

분위기 참고 하나.

움직임 참고 하나.

시간이 부족하면 제가 준비한 예시 중에서 고르면 됩니다.

### AI에게 줄 형식

```text
1. 사이트 주소 또는 스크린샷:
2. 마음에 드는 부분:
3. 내 홈페이지가 가져오면 좋을 것:
4. 절대 그대로 따라 하면 안 되는 것:
5. AI에게 줄 자료:
   URL / 스크린샷 / 색상 / 폰트 / 부품 이름 / 움직임 설명
```

## 38-45분: 결과물과 대화 기록을 보여준다

### 말하기

이제 제가 먼저 해본 결과물을 보여드리겠습니다.

여기서 중요한 건 결과물만 보는 게 아닙니다.

대화 기록을 같이 봐야 합니다.

AI로 만든 결과물은 한 번에 잘 나오지 않습니다.

처음에는 레퍼런스와 다르게 나올 수 있고, 캐릭터 퀄리티가 낮을 수 있고, 움직임이 거의 없을 수 있습니다.

그런데 이건 실패가 아닙니다.

AI 작업에서 진짜 실력은 첫 결과물을 보고 다시 지시하는 데서 나옵니다.

“별로야”라고 말하면 AI도 잘 모릅니다.

대신 이렇게 말해야 합니다.

```text
첫 화면이 너무 평범합니다.
Hero 문장을 더 크게 하고, 카드 수를 줄여주세요.
마우스를 올렸을 때 반응이 더 분명하게 보이게 해주세요.

단, 모바일 반응형과 DESIGN.md의 브랜드 방향은 유지해주세요.
```

이렇게 바꿀 것과 유지할 것을 같이 말하는 게 중요합니다.

### 보여줄 것

- 완성 예시 사이트
- `reference-dna.md`
- `prompt-pack.md`
- `DESIGN.md`
- QA 리포트 또는 스크린샷

### 피드백 포인트

- 대화 기록 전체를 길게 보여주면 늘어진다.
- 실패 장면 1개, 수정 요청 1개, 개선 결과 1개만 보여주는 것이 좋다.

## 45-53분: 실시간 시연

### 말하기

이제 실제로 어떻게 시작하는지 보여드리겠습니다.

여기서 여러분이 외워야 할 것은 명령어가 아닙니다.

흐름입니다.

브랜드 재료.

레퍼런스 증거.

프롬프트팩.

DESIGN.md.

그리고 제작.

이 순서만 기억하면 됩니다.

### 시연 순서

1. Codex에서 시작 프롬프트 입력
2. 브랜드 질문 1-2개만 답변
3. 레퍼런스 가이드 보여주기
4. 준비한 URL 또는 스크린샷을 넣는 장면 보여주기
5. `reference-dna.md`가 무엇인지 설명
6. `prompt-pack.md`가 왜 필요한지 설명
7. `DESIGN.md`를 제작 계약서라고 설명

### 말하기

우리가 직접 코딩을 다 하는 것이 아니라, AI가 일할 수 있는 순서를 만들어주는 겁니다.

AI에게 “알아서 해줘”라고 맡기는 게 아니라, 일의 기준을 주는 겁니다.

이 기준이 바로 `DESIGN.md`입니다.

### 시간 조절

- 실제 생성이 느리면 파일 예시를 바로 연다.
- 수강생 참여는 질문 1개만 받는다.
- 배포 실습은 마지막 10분 설명으로 넘긴다.

## 53-57분: 보안과 관리

### 말하기

홈페이지를 만들 때 조심해야 할 것도 있습니다.

API 키, 비밀번호, 개인 연락처, 결제 정보 같은 것은 코드에 그대로 넣으면 안 됩니다.

그리고 AI가 없는 경력이나 숫자를 만들어낼 때가 있습니다.

예를 들어 실제로 하지 않은 강의, 없는 고객 후기, 확인되지 않은 수치 같은 걸 멋있게 넣으면 안 됩니다.

브랜딩 페이지는 신뢰를 만드는 페이지입니다.

그래서 없는 내용을 멋있게 쓰는 것보다, 정확한 내용을 분명하게 쓰는 것이 더 중요합니다.

### 체크리스트

- API 키를 코드에 넣지 않기
- 비밀번호를 GitHub에 올리지 않기
- 없는 경력, 후기, 숫자 만들지 않기
- 카카오톡/스레드/블로그 링크 확인하기
- 모바일에서 깨지지 않는지 확인하기

## 57-60분: 배포와 마무리

### 말하기

마지막으로 배포입니다.

GitHub는 내 홈페이지 코드를 보관하는 곳입니다.

Vercel은 그 코드를 실제 링크로 만들어주는 곳입니다.

처음에는 낯설 수 있지만, 이것도 AI에게 단계별로 물어보면 됩니다.

이렇게 말하면 됩니다.

```text
내가 만든 정적 홈페이지를 GitHub에 올리고 Vercel로 배포하고 싶어.
윈도우 기준으로 한 단계씩 설명해줘.
내가 따라 하면 다음 단계로 넘어가줘.
```

오늘의 핵심은 모든 명령어를 외우는 것이 아닙니다.

내가 원하는 결과를 AI가 이해할 수 있게 정리하고, AI에게 단계별로 일을 시키는 관점을 배우는 것입니다.

오늘 만든 홈페이지는 최종본이 아니라 시작점입니다.

레퍼런스를 바꾸면 분위기가 바뀌고, 문장을 바꾸면 브랜드가 바뀌고, 움직임을 바꾸면 기억에 남는 방식이 바뀝니다.

중요한 건 내가 직접 다 코딩하지 않아도, AI와 대화하면서 내 브랜드 홈페이지를 계속 발전시킬 수 있다는 감각입니다.

### 마지막 한 문장

```text
홈페이지를 만드는 능력은 코드를 외우는 능력이 아니라,
내 브랜드를 AI가 알아들을 수 있는 말로 바꾸는 능력에서 시작합니다.
```

## 강의 후 안내

### 말하기

수업 후에는 오늘 보여드린 자료를 보고 같은 순서로 다시 진행하시면 됩니다.

막히면 AI에게 이렇게 말하세요.

```text
지금 나는 개인 브랜드 홈페이지를 만들고 있어.
현재 단계가 어디인지 먼저 확인해주고,
다음에 해야 할 일을 하나씩 질문해줘.
나는 초보자니까 어려운 용어는 쉽게 설명해줘.
```

## 강사용 운영 메모

- 레퍼런스 탐색을 수업 중 자유롭게 열어두면 시간이 무너진다.
- 수강생에게는 준비된 후보에서 고르게 한다.
- 대화 기록은 전체가 아니라 실패-수정-개선 한 사이클만 보여준다.
- 개발 용어는 반드시 쉬운 말로 번역한다.
- 배포는 직접 완주보다 “AI에게 단계별로 물어보는 관점”을 강조한다.
- 결과물보다 수정 요청 방식을 보여주는 것이 수업의 핵심이다.
